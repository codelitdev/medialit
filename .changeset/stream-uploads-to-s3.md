Uploads now stream straight to the bucket as S3 multipart uploads, for both regular and resumable (tus) uploads, instead of being written to the server's disk first. Resumable uploads can continue on any API instance. A rejected or abandoned upload leaves nothing in the bucket, and every upload is recorded as it starts, so the temp cleanup job also removes what a server crash leaves behind. With WebP on, only the WebP file is kept and its size is what counts toward storage. Resumable uploads must now declare their size up front. Part size and concurrency are set with `UPLOAD_PART_SIZE_BYTES` and `UPLOAD_PART_CONCURRENCY`. Requests no longer time out after five minutes; a connection is closed only after `REQUEST_IDLE_TIMEOUT_MS` with no data. Regular uploads per process are capped by `MAX_CONCURRENT_FORM_UPLOADS`, answering 503 with `Retry-After` over the cap. An upload a crash interrupts is cleaned up after `UPLOAD_STALE_MINUTES` (30) with no activity; resumable uploads stay resumable until they expire.
